## README에 넣을 B 부분 (초안)

### 기여 — B
- **분석 서버**: FastAPI + 로컬 Ollama(`llama3.1:8b`). 질문 → 계획 → 계산 → 검증 → 답변 구성 (`POST /api/dashboard/analyze`)
- **계획 검증**: 모델 초안은 참고만 하고 규칙 코드가 읽은 값이 우선. 모델이 없어도 동작
- **질문 이해**: 지역 20곳·업종 63개·기간, 점포당·구성비·증감(전 분기/전년)·합계, 판단 표현 8종을 지표로 번역
- **막힘 대응**: 이유와 서버가 통과를 확인한 제안 질문을 함께 안내, 데이터에 없는 질문은 지어내지 않음
- **이어 묻기**: A가 보낸 직전 질문 3개로 "그럼 홍대는?"을 이어받음 (서버 저장 없음)
- **창업·수입 답변**: 결론 문장 + 같은 조건 20곳 중 순위 + 증감 + 이어 물어보기
- **보안**: `X-API-Key`로 공개 서버를 보호, 키는 Vercel 환경변수에만 두도록 프록시 예시 제공
- **검증·운영**: 테스트 자동화, 질문 평가셋(기본 116 + 처음 본 표현 21), 서버·ngrok 운영과 병합 후 재시작

### 회고 — B (초안, 직접 고쳐 쓰세요)
- **가장 크게 배운 것**: "모든 질문에 답하는 AI"가 아니라 **"틀린 답을 못 하게 하는 AI"**가 먼저였다. 막을 때는 이유와 서버가 확인한 다음 질문을 같이 줘야 사용자가 막히지 않는다. 그리고 C가 지적했듯이 검증은 숫자와 질문의 뜻 둘 다 봐야 한다 (전년 대비 오답, 설명 문구 가로채기).
- **다음에 다르게 할 한 가지**: 질문 평가셋(말투 다른 질문 + 코드가 처음 보는 표현)을 **개발 첫날부터** 만들고, 표현 규칙을 추가할 때마다 반례를 같이 넣겠다. 이번에는 사용자 질문을 보고 규칙을 늘리는 순서였고, 낱말 포함 검사 때문에 "유망한→망한" 같은 오류가 뒤늦게 나왔다.
