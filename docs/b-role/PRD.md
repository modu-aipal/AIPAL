| 항목 | 내용 |
|---|---|
| 문서 버전 | v0.1 (main `bbb905a`, PR #31까지 병합 반영) |
| 작성일 | 2026-11-24 |
| 담당 | B (genJ-M) |

## 1. 개요

사용자가 자연어로 던진 상권 질문("성수에서 카페 차리면 괜찮을까?")을 **검증된 분석 계획**으로 바꾸고, C의 계산 엔진에서 받은 숫자만으로 **근거가 붙은 답변**을 만들어 A 대시보드에 돌려주는 AI 분석 서버.

한 줄 정의: **"AI는 질문을 해석만 하고, 숫자는 계산 엔진에서만 가져와 검증한 뒤 답하는 서버."** 질문 해석은 로컬 LLM(Ollama)과 규칙 코드가 같이 하되, 계획은 코드가 최종 검증한다. 숫자를 만들지도 고치지도 않는다.

팀 내 위치:

```
사용자 → A(지도·리포트·펄이) ─질문(+직전 질문 history)→ B(질문 이해·계획 검증) → C(계산) → B(검증·답변 구성) → A(표시)
              └─ A → B 호출은 Vercel 서버 함수가 X-API-Key 를 붙여 전달 (PR #17)
```

## 2. 문제 정의

| 문제 | 증상 |
|---|---|
| LLM이 숫자를 지어낸다 | 그럴듯하지만 근거 없는 매출·순위가 답으로 나온다 |
| 질문 표현이 사람마다 다르다 | "잘나가는", "뜨는", "한 곳당", "가게별", "전년 같은 분기" 같은 말이 같은 지표를 뜻한다 |
| 모델이 질문을 잘못 해석해도 모른다 | 숫자는 맞는데 질문의 뜻과 다른 답 (예: 전년 대비를 전 분기 대비로 답함) |
| 데이터에 없는 질문에 억지 답을 한다 | 월별 매출, 임대료, 진료과목별 매출을 물어도 숫자를 만들어 낸다 |
| 막히면 사용자가 막막하다 | "답할 수 없어요"만 오면 다음에 뭘 물어야 할지 모른다 |
| 앞 질문을 기억하지 못한다 | "그럼 홍대는?"에 되묻기만 한다 |
| 서버가 공개 주소에 노출된다 | 아무나 호출하면 로컬 PC의 모델과 엔진이 쓰인다 |

### 우리의 접근

1. **계획을 코드가 검증한다.** 모델이 낸 초안(`PlanDraft`)은 참고만 하고, 규칙 코드(`planner.evaluate`)가 질문에서 직접 읽은 값이 모델 값보다 우선한다. 모델이 없거나 늦어도 규칙만으로 계획을 만든다.
2. **숫자는 계산 엔진만.** B는 계산 요청(`CalcRequest`)을 만들고 응답을 검증(`verify_result`)한 뒤 문장으로 옮긴다. 모든 숫자에는 근거(기간·지표·연산)를 붙인다.
3. **모르면 모른다고, 막힐 때는 이유와 제안을 같이 준다.** 서버가 직접 통과 여부를 확인한 질문만 제안한다.
4. **판단 표현도 데이터로 번역한다.** "창업하기 좋은 곳", "수입은 어때"를 임의로 판단하지 않고 점포당 매출·증감 같은 지표와 순위로 바꿔 답하고, 한계 문구를 붙인다.
5. **가정은 숨기지 않는다.** 질문에 없던 기간·지표를 기본값으로 정하면 답변에 "※ 기준:"으로 밝힌다.

## 3. 목표 / 비목표

### 3.1 MVP 목표

| # | 목표 | 측정 방법 |
|---|---|---|
| G1 | 숫자 무결성 | 답변 속 숫자 전부가 C 결과와 같다. 지어낸 숫자 0개 (C의 PEARL_TEST 판정) |
| G2 | 질문 이해 | 평가 질문셋(116문항)에서 규칙만으로 115문항 통과, 처음 본 표현 21문항 별도 측정 |
| G3 | 안전한 거절 | 데이터에 없는 질문은 이유와 서버가 검증한 대체 질문을 함께 안내 |
| G4 | 연동 | A가 `{area, sql, text}`로 받아 그대로 표시 (규격 `docs/DASHBOARD_API.md`) |
| G5 | 접근 제한 | `X-API-Key` 없이는 401, 키는 클라이언트 코드에 없음 |
| G6 | 비용 | 유료 외부 AI API 없음 (로컬 Ollama `llama3.1:8b`) |
| G7 | 이어 묻기 | 직전 질문 최대 3개로 "그럼 홍대는?"을 이어받되, 애매하면 이어받지 않고 되묻기 |

### 3.2 MVP 비목표

- 숫자를 계산·보정하는 것 (계산은 C)
- 화면 표시·배포 (A)
- 대화 내용 저장 (서버는 질문 원문을 저장하지 않는다. 이어 묻기는 A가 보낸 `history`만 쓴다)
- 계정·권한·결제
- A(`dashboard/`)와 C(`calc_engine/`) 코드 수정
- 데이터에 없는 질문(월별·임대료·진료과목별 매출)에 대한 추정 답변

## 4. 대상 사용자

### 페르소나 A — "상권이 궁금한 소상공인·창업 준비자"
- 펄이에게 "성수 카페 점포당 매출", "홍대에서 창업하기 좋은 업종은?"처럼 편하게 묻는다
- 니즈: 말투가 달라도 알아듣고, 못 알아들으면 어떻게 물으면 되는지 알려 주는 답
- 이탈 요인: 계속 되묻기만 하는 답, 근거 없는 추천

### 페르소나 B — "숫자를 의심하는 검증자 (심사위원·팀원)"
- 니즈: 이 숫자가 어떤 계산으로 나왔는지, AI가 지어낸 건 아닌지
- 보는 곳: 답변의 근거 줄, 실행한 SQL(또는 "SQL 없이 pandas 계산"), 한계 문구, Mock 표시

> **설계 원칙:** AI가 말을 잘하는 것보다 틀린 말을 못 하게 하는 것이 먼저다. 애매하면 이어받지 않고, 모르면 안내한다.

## 6. 기능 요구사항

### 6.1 P0 — MVP 필수

#### F-B01. 질문 → 분석 계획
- 지역 20곳·업종 63개·기간(분기)·지표(매출 합계·평균·증감률·점포당·구성비)·정렬·상위 N을 읽는다.
- 모델 초안은 30초·400토큰 안에서만 쓰고, 실패·시간 초과면 규칙만으로 진행한다.
- 코드가 읽은 값이 모델 값보다 우선한다.

#### F-B02. 계산 요청·검증
- 계획을 계산 규격(1.0, 점포당·비율은 1.1)으로 바꿔 C에 보낸다 (`CALC_MODE=http`).
- 응답을 검증(`verify_result`)해 어긋나면 답하지 않고 오류로 돌린다.
- 증감의 기준 기간은 요청에 명시해 보낸다.

#### F-B03. 답변 구성 (`{area, sql, text}`)
- 결론 → 목록 → 해석 → 근거·가정(※) 순서의 줄바꿈 구조.
- 순위 질문의 하한: 증감·점포당 순위는 매출 1억 원 이상 그룹만, 폐업률·개업률 순위는 점포 평균 30개 이상 그룹만.
- Mock이면 표시한다.

#### F-B04. 막힘 응답
| 상황 | 응답 |
|---|---|
| 필수 조건이 빠짐·애매함 | HTTP 422 `needs_clarification` + 이유 + 서버가 통과를 확인한 제안 질문 |
| 데이터 정의 질문 | HTTP 200 `status=info` (고정 설명) |
| 범위 밖 기간(2021Q1~최신 분기 밖) | 되묻기 (`bad_period`) |
| 계산 실패 | 5xx 사유 (숫자를 내지 않음) |

#### F-B05. 접근 제한
- `X-API-Key` 헤더 검증(`secrets.compare_digest`), `/health`만 인증 없이 허용, CORS는 환경변수로 제어.

### 6.3 향후

- B의 `reason`·`suggested_questions`를 A 화면 예시 버튼에 쓰기 (PRD Q-02, A와 협의)

## 7. 주요 흐름

```
[질문 + history] → [API 키 검증]
        │
        ▼
[이어 묻기 판별(follow_up)] → 직전 질문에서 빠진 조건만 상속
        │
        ▼
[모델 초안 PlanDraft (30초, 실패하면 건너뜀)] → [planner.evaluate: 규칙·코드 값이 우선]
        │                                              │
        │                         ok ───────────────────┤
        │                         info → 고정 설명(200)  │
        │                         clarify → 422 + 제안   │
        ▼                                              ▼
                                               [build_request] → [C /calculate]
                                                       │
                                               [verify_result] → [ranking.rank]
                                                       │
                                       [compose + (창업·수입이면 순위·이어 묻기)]
                                                       │
                                               [explain] → {area, sql, text}
```

## 8. 비기능 요구사항

| 구분 | 요구사항 |
|---|---|
| 정확성 | 숫자는 C 결과 그대로. 반올림·단위 표기만 B가 한다 |
| 안전 | 키 인증, 키는 서버 `.env`와 Vercel 환경변수에만. 질문 원문은 저장하지 않음 |
| 성능 | 모델 초안 30초 제한, 답변 해석문 생성도 시간 제한 (초과 시 코드가 만든 문장으로 대체) |
| 가용성 | 모델이 멈춰도 규칙만으로 답한다. C가 죽으면 숫자 없이 오류 |
| 재현성 | 질문 해석은 평가 질문셋으로 회귀 확인, 테스트 자동화 |
| 설정 | 모델·주소·키·CORS는 `.env`로, 코드 수정 불필요 |
| 언어 | 한국어 단일 |

## 11. 범위 밖 · 범위 조정 기록

| 항목 | 결정 | 이유 |
|---|---|---|
| 모델이 모든 질문에 자유롭게 답하는 방식 | **쓰지 않음** | 숫자를 지어낼 수 있다. 계획만 모델이 돕고 답은 계산 결과로만 만든다 |
