# 데이터 정의 (C 담당)

계산 엔진(`calc_engine/`)이 쓰는 데이터와, 각 정의의 근거를 정리한다. 2026-11-23 기준 (제공 기관 답변 반영).

## 1. 출처
- 서울 열린데이터광장 **OA-22175 「서울시 상권분석서비스(추정매출-행정동)」**
- 저작권자 서울특별시, 제공 서울신용보증재단(데이터분석팀, 02-2174-5075), 이용허락범위 **제한 없음**
- **2021~2025년**: '파일내려받기'의 연도별 zip (각 약 11MB, 압축 해제 시 약 30MB, **CP949**, 53개 컬럼, 연도별 구성 동일)
- **2026년 1·2분기**: 분기 파일은 제공되지 않고 2026년 연간 파일은 2027년에 올라올 예정이라(제공 기관 답변(열린데이터광장 문의, 2026-11-20)) **Sheet 화면의 CSV 내려받기**(화면 기본 조건 그대로, 2025Q1~2026Q2, 45MB, CP949)를 씀. 2026-11-19 받음
  - 같은 데이터인지 확인: Sheet의 2025년 67,113행이 공식 2025년 파일과 **숫자 전 칸 일치**. 다른 곳은 동 이름 7개뿐이고 원인은 Sheet 내려받기에서 '·'가 '?'로 깨진 것(예: 상계6·7동). 20곳 중 종로1·2·3·4가동이 여기에 해당하지만, 동 이름은 매핑표 기준으로 바꿔 쓰므로 가공 파일에는 깨짐이 없음 (테스트로 확인)
  - 2026Q1과 2026Q2는 행 수가 같지만(16,659) 금액이 같은 행은 209개뿐이라 복사본이 아님
- **점포 데이터**: 서울 열린데이터광장 **OA-22172 「서울시 상권분석서비스(점포-행정동)」** (같은 기관·같은 분기·같은 행정동 코드와 업종 코드, 업종 100개). 2021~2025년은 연도별 zip, 2026년 1·2분기는 Sheet CSV 내려받기(2026-11-23 받음). Sheet의 2025년 141,218행이 공식 파일과 전 칸 일치
- **추정 매출**(카드 데이터 기반 추정치)이며 실제 매출이 아니다. 산출식: 추정매출액 = 카드결제금액 ÷ 보정비율 (상권분석서비스 이용안내). 반영 카드사는 **신한카드** (제공 기관 답변(열린데이터광장 문의, 2026-11-20))

## 3. 지역 정의 (대시보드와 같은 20곳, 행정동 23개)
- 기준 파일은 대시보드가 쓰는 **`data/area_map.csv`**. C의 `calc_engine/data/region_map.csv`는 이 파일에서 만들고, 둘이 같은지 테스트(`test_region_map_matches_dashboard_area_map`)로 지킨다
- 처음 5곳: 성수(성수1가1동·성수1가2동·성수2가1동·성수2가3동), 홍대(서교동), 건대(화양동), 강남(역삼1동), 이태원(이태원1동)
- 추가 15곳(동 하나씩): 제기동, 노량진1동, 노량진2동, 가산동, 한강로동, 종로1~4가(종로1·2·3·4가동), 가락1동, 여의동, 압구정동, 청담동, 신사동(강남구 11680510), 영등포동, 명동, 독산1동, 논현1동
- **반드시 코드로 합친다**: 원본에 이름이 같은 동이 있음 (신사동 관악구 11620685 / 강남구 11680510 — 우리는 강남구)
- 지역마다 포함 동 개수가 다르다(성수 4, 나머지 1). 지역 총액 비교 시 함께 안내 (엔진 notes `region_dong_count`)
- 지역은 우리가 정한 행정동 묶음이며 실제 핫플 범위와 다를 수 있다

## 5. 정의별 근거 수준
| 항목 | 판단 | 근거 수준 | 근거 |
|---|---|---|---|
| `당월_매출_금액`·`당월_매출_건수`의 기간 | **분기 3개월 합계** | **확인됨** (제공 기관 답변(열린데이터광장 문의, 2026-11-20): "해당분기 3개월 매출액의 합계". 사이트 대조로도 일치) | 상권분석서비스, 서교동 2025년 4분기: 지도 매출 3,688.9억 원 = 데이터 368,888,000,781원. ÷3 ÷점포수(8,820) = 13,941,345원 → 사이트 "점포당 월평균 매출 1,394만 원" 일치. 건수 14,663,460 ÷3 ÷8,820 = 554.2 → "월평균 매출건수 554건" 일치. **2026년 2분기도 같은 방식으로 일치**: 매출 364,283,677,777원 = 지도 3,642.8억 원, ÷3 ÷8,783 = 13,825,332원 → "1,383만 원", 건수 → 582.1건 → "582건". 사이트 요일별 매출 단위 "3개월간 점포당 평균" |
| 세부 컬럼(주중·주말, 요일, 시간대)의 기준 | 총계와 같은 기준 | **확인됨** (전 행 대조) | 20곳 24,340행에서 금액은 전부 합 = 총계. 건수는 시간대 합만 압구정동 2개 행(2024Q1·Q2)에서 1건 모자람 (원본 값 그대로) |
| 성별·연령 합계 < 총계 | 성별·연령을 구분할 수 없는 **법인 매출**이 총계에 포함되기 때문 | **확인됨** (제공 기관 답변(열린데이터광장 문의, 2026-11-20)) | 서울 전체 2021Q4 성별 부족분 중앙값 1.6%, 최대 100.0%(반올림). 답변에 외국인 결제 언급은 없음 |
| 2021~2023년을 2024년 이후와 같은 기준으로 비교 | **비교 가능** | **확인됨** (제공 기관 답변(열린데이터광장 문의, 2026-11-20)) | "표준단위구역 데이터 개편 이후 새 기준으로 재산출 진행하여 2021년부터 데이터를 제공". 엔진의 2023년 이전 주의 안내는 없앰 |
| 카드사 범위 | **신한카드** | **확인됨** (제공 기관 답변(열린데이터광장 문의, 2026-11-20)) | 사이트 리포트의 "5개 카드사", 서울디자인재단 보도자료의 "BC·KB·신한"은 이 데이터에 해당하지 않음 |
| 점포 데이터 '점포_수'의 뜻 | **프랜차이즈를 뺀 일반 점포**. 전체 점포는 '유사_업종_점포_수' | **확인됨** (사이트 대조 + Sheet 컬럼명 대조) | 서교동 2025Q4: '유사_업종_점포_수' 합 8,820 = 사이트 "점포수 8,820", '점포_수' 합 8,101 = 사이트 "일반점포 8,101". 모든 행에서 유사 = 점포 + 프랜차이즈. Sheet 내려받기는 같은 값을 '전체_점포_수'·'일반_점포_수'로 부름(141,218행 전 칸 일치). 매출 ÷3 ÷8,820 = 사이트 점포당 월평균 1,394만 원 |
| 원본 개업_율·폐업_률 | 개업(폐업) 수 ÷ 전체 점포 수 × 100 반올림 | 데이터 대조 | 약 98% 행이 일치 (일반 점포로 나누면 89%). 엔진은 반올림 없이 직접 계산 |
- **쓰지 않는 해석**: "당월 매출 = 분기 월평균이므로 ×3"(서울디자인재단 보도자료, 점포-상권 데이터 대상). 행정동 데이터에 적용하면 사이트 숫자와 3배 어긋남

## 6. 표시 규칙 (화면·설명 문장 공통)
API는 반올림하지 않은 값을 보낸다. 표시할 때만: 금액 = 억 원 소수 첫째 자리(5,192.5억 원) / 비율 = % 소수 첫째 자리(44.5%) / 증감률 = 부호 붙인 %(+4.8%) / 건수 = 쉼표 정수(224,959건)

## 7. 한계와 다음 개선 (발표용)
| 한계 | 이유 | 다음 개선 |
|---|---|---|
| **진료과목별 매출을 알 수 없음** (예: "강남 성형외과 매출") | 데이터 업종이 생활밀접업종 62개뿐이고 병원은 일반의원·치과의원·한의원 3개. 성형외과는 일반의원에 섞여 있는 것으로 보임. 진료과목별 카드 매출은 공개되지 않고, 건강보험 진료비 통계는 성형 같은 비급여 진료가 거의 안 잡혀 매출로 쓰면 틀림 | 진료과목이 적힌 병원·상가 목록 공공 데이터를 행정동에 연결해 **"진료과목별 병원 수"** 제공 (매출이 아닌 개수). 지금은 "따로 없고 일반의원에 포함"이라고 안내 |
