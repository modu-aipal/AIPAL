# 대시보드(A) 연동 API

## `POST /api/dashboard/analyze`

질문 → 분석 계획(펄이) → 계산 엔진(C) → 로컬 Ollama 설명 → `{area, sql, text}`

요청

```json
{"question": "홍대의 음식점 분기별 매출을 보여줘."}
```

응답 200 (본문은 3개 필드로 고정)

```json
{
  "area": "hongdae",
  "sql": "",
  "text": "…계산 결과에 있는 수치로만 만든 설명…"
}
```

| 필드 | 규칙 |
|---|---|
| `area` | 지역 식별값. **`data/area_map.csv`의 `area_id`와 같다**(대시보드 `AREAS`의 `id`). 20곳: `jegi nr2 gasan hangang jongno gangnam garak hongdae nr1 yeouido apgu seongsu cheongdam sinsa ydp myeong doksan nonhyeon kondae itaewon`. 건대는 `kondae`. 복수 지역은 쉼표 연결(`"seongsu,hongdae"`), 전체 순위·업종 비교처럼 지역을 지정하지 않으면 `""` |
| `sql` | 계산 엔진이 `executed_sql`로 **실제 실행한 SQL을 보고했을 때만** 그 값. Pandas 계산이면 `""`. B는 SQL을 생성·실행하지 않음 |
| `text` | 계산 결과의 수치·근거만 사용. 끝에 서버가 붙이는 `※ 기준`·`※ 주의` 줄이 있다 (아래) |

## 질문 유형 (펄이가 해석)

| 유형 | 예 | 처리 |
|---|---|---|
| 단일 조회 | "강남 매출 알려줘", "이태원 점포당 월평균 매출은?" | 지역 1곳의 값 |
| 지역 비교 | "성수와 홍대의 카페 매출을 비교해줘" | 지역 2곳 이상, 지역별 값 |
| 업종 비교 | "2024년 강남에서 매출이 증가한 업종은?" | 업종별 값 |
| 분기별 추이 | "홍대 음식점 분기별 매출 추이" | 분기별 값 |
| 상권 순위 | "최근 1년 가장 많이 성장한 상권은?", "카페 매출이 가장 낮은 상권은?" | 20곳 전체를 계산해 **코드가** 정렬 (높은 순/낮은 순) |

- 지표: 추정매출, 매출 건수, 주중·주말·성별 매출, **점포 수**(분기 평균), 일반·프랜차이즈 점포 수, 개업·폐업 점포 수, **점포당 월평균 매출**(`per_store`).
- 지역 이름은 별칭도 받는다(여의도, 압구정, 청담, 종로, 영등포, 논현, 독산, 홍대입구, 건대입구, 역삼 …). **노량진**은 1동·2동 중 어느 쪽인지 되묻는다.

### 질문에 없는 조건은 기본값으로 가정하고 답변에 밝힌다
| 빠진 정보 | 기본값 |
|---|---|
| 업종 | 전체 업종 합계 |
| 기간 | 단일 조회·비교·순위·업종 비교 = **최근 4분기**, 추이 = 전체 분기 |
| "최근", "최근 N년/N분기", "올해", "작년" | **최신 분기** 기준 (C 엔진 `/health`에서 읽음, 못 읽으면 `LATEST_QUARTER`) |
| 증감률의 기준 기간 | 현재 기간 직전의 같은 길이 기간 |
| 순위 지표 | "성장·증가" 단어가 있으면 증감률, 없으면 매출 합계 |

`text` 끝에 `※ 기준: 업종: 전체 업종 합계 · 기간: 최근 4분기(2025Q3~2026Q2)`처럼 항상 붙는다.

## 질문이 막힐 때: 이유 + 서버가 검증한 제안

HTTP **422** `needs_clarification`. 응답 `detail`:

```json
{
  "error": "needs_clarification",
  "clarification_question": "추천·창업 성공 여부 판단은 지원하지 않습니다. … 이렇게 물어보세요: ① 성수 카페 분기별 매출 추이 보여줘 ② 성수와 홍대의 카페 매출을 비교해줘 ③ 성수 카페 점포당 월평균 매출 알려줘",
  "missing_fields": [],
  "reason": "추천·창업 성공 여부 판단은 지원하지 않습니다. 대신 데이터로 비교해 볼 수 있습니다.",
  "suggested_questions": ["성수 카페 분기별 매출 추이 보여줘", "성수와 홍대의 카페 매출을 비교해줘", "성수 카페 점포당 월평균 매출 알려줘"]
}
```

- `suggested_questions`는 **그대로 다시 보내면 반드시 답이 나온다**. 서버가 모델 없이 규칙만으로 통과하는 것만 남긴다(최대 3개). 질문에 나온 지역·업종을 이어받는다.
- 문구(`clarification_question`)에도 제안이 들어 있어서 A가 `suggested_questions`를 쓰지 않아도 보인다. 버튼으로 보여 주면 더 좋다(선택).

| 막힌 이유 | 안내 |
|---|---|
| 추천·창업 판단 | 지원하지 않음 + 같은 지역·업종의 비교 질문 제안 |
| 월별 | 분기 단위 데이터 + "분기별 추이" 제안 |
| 비중·비율 | 아직 미지원 + 가까운 지표 제안(예: 주말 매출이 가장 높은 상권은?) |
| 지원 지역 밖(예: 잠실) | 지원 지역 20곳 목록 + 예시 질문 |
| 한 지역만 두고 "비교" | 비교할 지역 제안 |
| 분기 경계가 아닌 기간(2025년 2월) | "2025년 1분기" 제안 |
| 노량진 | 1동·2동 제안 |

## Mock 표시 (실제 분석으로 오인 방지)
- 계산 결과가 Mock이면 `text`가 `[테스트용 Mock 데이터 기반 - 실제 분석 결과가 아닙니다]`로 시작하고, 응답 헤더 `X-Is-Mock: true`, `X-Data-Source: MOCK_TEST_DATA`가 붙는다.
- 본문 필드는 합의된 3개를 유지하기 위해 `is_mock` 필드를 추가하지 않았다.
- `APP_ENV=production`에서는 Mock 모드 자체가 503으로 차단된다.

## `text` 검증과 덧붙이는 문구
1. 계산 결과에서 만든 사실 목록(FACTS)만 모델에 전달한다. 순위 질문은 코드가 정렬한 순서로 준다.
2. 모델 출력의 모든 숫자를 FACTS와 대조한다. FACTS에 없는 숫자(차이, 배수, 임의 수치)가 있으면 거부.
3. 추천·예측 성격 표현(추천, 유망, 전망, 유리, 적합 등)이 있으면 거부. **순위 질문에서만** "가장", "1위" 같은 정렬 표현을 허용한다.
4. 거부되거나 모델이 늦으면(60초) 계산 결과를 그대로 나열한 **결정적 템플릿 문장**으로 대체한다 (오류로 처리하지 않음).
5. 결과 행이 없으면 모델 호출 없이 "조건에 해당하는 계산 결과가 없습니다."를 반환한다.
6. 모델과 무관하게 코드가 끝에 붙이는 줄: `※ 기준`(가정), `※ 주의`(2023년 이전 기준 미확정 등 엔진 notes), 지역별 행정동 수, **시장·도매형 상권 주의**(`dashboard_data.json`의 cautions), 업종 묶음.
- 한계: 숫자·금지어 외의 정성적 해석(예: "증가하는 추세")은 자동 검증하지 않는다.

## 질문 해석이 멈출 때
- 모델의 질문 해석(구조화 출력)은 30초·400토큰 안에 끝나야 한다. 넘으면 **모델 없이 서버 규칙**(지역·업종·기간·지표 추출)으로 처리한다. 모델이 JSON 형식을 어긴 경우는 502 오류로 알린다.

### 오류 응답 (`detail` 포함)
| 상태 | 상황 |
|---|---|
| 422 `needs_clarification` | 위 표. 계산하지 않으며 본문은 분석 응답이 아님 |
| 422 `plan_validation_failed` | 계획이 데이터셋 규칙 위반 |
| 502 | 모델 출력 스키마 불일치 / 계산 엔진 응답 불일치 / 엔진이 `status=error` (`engine_error` 포함) |
| 503 | Ollama·계산 엔진 연결 불가, Mock 차단 |
| 504 | 계산 엔진 시간 초과 |

## 합의가 필요한 사항 (A ↔ B)
1. **복수 지역·전체**: 지역 비교는 `area`를 쉼표로 잇고, 전체 순위는 `""`. 배열 또는 `areas` 필드 추가, 순위 1위 지역으로 지도 이동 같은 방식을 협의해야 한다.
2. **재질문 표현**: 현재 HTTP 422 + `detail`. A가 200 본문의 `text`로 받길 원하면 변경 가능(단, 분석 결과와 구분 필요). `suggested_questions`를 버튼으로 보여 줄지도 협의.
3. **Mock 표시**: 헤더 + `text` 접두 방식. 본문에 `is_mock` 필드 추가 여부.
4. 한 응답에 지표가 여러 개이거나 그룹이 많을 때(순위 20곳) `text` 길이/형식. 지금은 정렬된 상위 몇 곳만 말하도록 모델에 맡기고, 모델이 실패하면 20곳을 모두 나열한다.
