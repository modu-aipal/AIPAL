## 0. 이 문서의 사용법

### 0.1 단위 체크리스트와의 차이

| | 단위 체크리스트 (WORK_UNITS) | **최종 체크리스트 (이 문서)** |
|---|---|---|
| 시점 | 각 단위 구현 직후 | 전체 완료 후 제출 직전 |
| 범위 | 그 단위 하나 | **대시보드 전체 + B·C와 함께 도는지** |
| 관점 | "이 화면이 되는가" | "**숫자가 C와 같은가 · 끊겨도 버티는가 · 이상한 입력을 막는가**" |
| 환경 | 로컬 `http.server` | **Vercel 본 주소 + 실제 B(ngrok) + 데스크톱·실제 폰** |

### 0.2 수행 규칙

1. **본 주소(aipal-sangkwon-pulse.vercel.app)로 수행한다.** 로컬에서만 된 것은 근거가 되지 않는다.
2. **먼저 본 주소가 최신인지 본다.** `/sw.js`의 `VERSION`이 저장소와 같아야 한다.
3. **강력 새로고침(Cmd+Shift+R) 후 확인한다.** 서비스 워커 저장본으로 예전 화면을 보지 않도록.
4. **숫자는 C 파일로 대조한다.** "그럴듯해 보인다"는 통과가 아니다.
5. **실패 항목은 등급을 매겨 기록한다.** (§0.3)
6. 이 대시보드에는 계정·저장 데이터가 없다. 로그인·권한 항목은 해당 없음으로 적고, 대신 **API 키 노출·B 답변 주입·외부 스크립트·주소 바꿔치기**를 본다.

### 0.3 결함 등급과 판정

| 등급 | 정의 | 처리 |
|---|---|---|
| **Blocker** | C와 다른 숫자 표시, API 키 노출, B 답변이 HTML로 실행됨, 페이지가 안 열림 | **1건이라도 있으면 제출 불가** |
| **Major** | 주요 화면·펄이 질문이 안 됨, 폰에서 못 씀, B 끊김 시 화면 멈춤 | 수정 후 재점검 |
| **Minor** | 문구·배치·사소한 표시 | 기록만 하고 제출 후 처리 가능 |

> Part C(보안·무결성) 실패는 기본적으로 Blocker로 본다. Minor로 내리려면 근거를 기록한다.

### 0.4 판정

```
Blocker 0건  AND  Major 0건  →  제출 승인
그 외                        →  제출 보류
```

# Part B · 실패 · 비정상 입력 대응

> B가 없거나, 이상하게 물었을 때 화면이 버티는가.

## B1. B 연결 실패

- [ ] B 서버 끔(또는 `?api=https://없는주소`) → 오류 화면 없이 "AI 분석 서버에 연결할 수 없어요 · 대시보드 데이터로 답해요"
- [ ] 그 상태에서 내장 데이터로 답할 수 있는 질문 → "대시보드 데이터로 답했어요"
- [ ] 150초 넘게 응답 없음 → 시간 초과 안내 (B 쪽 지연 재현 필요)
- [ ] `?api=off` → 펄이 직접 질문이 내장 데이터로만 답

## B2. B 응답 종류

- [x] 422 재질문 → 안내 + 예시 버튼 + "서버 원문" 접기 (11/23 "강남의 성형외과 얼마야?")
- [x] 예시 버튼을 누르면 그 질문으로 다시 물음 (11/23)
- [ ] 502 (예: "2030년 1분기 강남 매출") → 사유 표시, 화면 멈춤 없음
- [ ] 401 (B가 API 키를 다시 켰을 때) → 사유 표시
- [ ] Mock 응답 → "테스트용 Mock 데이터 · 실제 분석 결과 아님" 배지

## B3. 입력 경계값

- [ ] 빈 입력 → 전송 안 됨 또는 안내
- [ ] 아주 긴 입력(1,000자) → 화면 깨짐 없음
- [ ] 이모지·특수문자만 입력
- [ ] 같은 질문 연타 → 마지막 답만 표시 (앞 답이 뒤늦게 덮어쓰지 않음)
- [ ] 지도 80곳 동이 들어간 질문 → B로 안 가고 내장 데이터 + 이유 문구

## B4. 가게 검색 입력

- [ ] 결과 0건 검색어 → 0곳 표시, 오류 없음
- [ ] `지하`, `반지하`, `1층`, `01층` 같은 층 표기
- [ ] 가게 파일을 못 받았을 때(오프라인 첫 방문) → 안내, 화면 멈춤 없음

## 0. 이 문서의 사용법

### 0.1 단위 체크리스트와의 차이

| | 단위 체크리스트 (WORK_UNITS) | **최종 체크리스트 (이 문서)** |
|---|---|---|
| 시점 | 각 단위 구현 직후 | 전체 완료 후 제출 직전 |
| 범위 | 그 단위 하나 | **B 전체 + A·C와 함께 도는지** |
| 관점 | "이 질문이 풀리는가" | "**숫자가 C와 같은가 · 지어내지 않는가 · 막을 것을 막는가**" |
| 환경 | 로컬 `pytest`, 로컬 포트 | **공개 주소(ngrok) + 본 주소(Vercel) 경유** |

### 0.2 수행 규칙

1. **공개 주소로 수행한다.** ngrok 주소와 A 본 주소(aipal-sangkwon-pulse.vercel.app) 경유 모두. 로컬에서만 된 것은 근거가 되지 않는다.
2. **먼저 서버가 최신 main인지 본다.** 로컬 `git log -1`이 main 최신 커밋과 같고 서버를 그 뒤에 재시작했는지 확인한다.
3. **숫자는 C 정답표·직접 계산으로 대조한다.** "그럴듯해 보인다"는 통과가 아니다.
4. **질문은 말투를 바꿔서 여러 번 묻는다.** 같은 뜻 3가지 이상.
5. **실패 항목은 등급을 매겨 기록한다.** (§0.3)
6. 이 서버에는 계정·저장 데이터가 없다. 로그인·권한 항목은 해당 없음으로 적고, 대신 **API 키·프롬프트 주입·모델 출력 신뢰·지어낸 숫자**를 본다.

### 0.3 결함 등급과 판정

| 등급 | 정의 | 처리 |
|---|---|---|
| **Blocker** | C와 다른 숫자를 맞다고 답함, 지어낸 숫자, 키 없이 호출 가능, 키·비밀값 노출, 서버 시연 불가 | **1건이라도 있으면 제출 불가** |
| **Major** | 질문 뜻과 다른 답, 한계·기준을 잘못 밝힘, 주요 질문이 막힘, 지원 질문이 오류 | 수정 후 재점검 |
| **Minor** | 문구·사소한 표현, 드문 표현을 못 알아들음 | 기록만 하고 제출 후 처리 가능 |

Blocker 0건  AND  Major 0건  →  제출 승인
그 외                        →  제출 보류

## AI 활용 · 디버깅 사례 (B)

### 사례 1 — "유망한"이 "망한"으로 읽힘
- **현상**: "홍대는 유망한 상권이야?"를 위험(폐업) 질문으로 해석했다.
- **원인**: 위험 표현을 낱말 "망한"이 포함되는지로 찾았다. "유망한" 안에도 "망한"이 있다.
- **수정**: 앞 글자를 확인하는 정규식(lookbehind)으로 "유망·희망"을 제외했다.
- **재검증**: 위험·전망 표현 테스트에 "유망한"·"희망적인" 사례를 추가했다 (`tests/test_bot_questions.py`).
- **AI 활용 포인트**: 모델이 아니라 규칙이 낸 오류였다. 낱말 포함 검사는 짧은 낱말일수록 다른 말에 숨어 있을 수 있어 반례 질문을 평가셋에 넣어 둔다.

### 사례 2 — 숫자는 맞는데 질문의 뜻이 달랐던 N8 (C가 찾음)
- **현상**: "전년 같은 분기 대비"를 물었는데 전 분기 대비(+10.3%)로 답했다. 정답은 +4.8%.

- **수정**: 전년 대비 표현을 인식해 기준 기간을 요청에 명시하고, 답변에 어떤 기준인지 밝혔다 (PR #28).
- **재검증**: 이태원 2025Q4 +4.8%가 C 정답표와 같다. C의 `pearl_eval.py` 재실행은 제출 직전에 한다.
- **AI 활용 포인트**: 검증은 숫자와 질문의 뜻 둘 다 봐야 한다는 C의 지적 그대로다.

## 4. AI 활용 · 디버깅 사례 3 (C) — '당월 매출'의 뜻
- **현상**: 처음에 '당월_매출_금액'을 이름 그대로 **한 달 매출**로 보고, 분기 값으로 만들려고 ×3 하는 방안을 검토했다.
