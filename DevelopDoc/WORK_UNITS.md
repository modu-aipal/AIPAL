## 1. 분할 원칙

### 1.1 왜 나누는가

1. **화면 오류를 좁히기 위해** — 지도·패널·펄이·가게 검색을 한 번에 바꾸면 무엇이 깨졌는지 찾기 어렵다.
2. **팀 경계 보호** — B·C 파일을 건드리지 않고 `dashboard/`·`data/` 안에서 끝나는 단위로 나눈다.
3. **데이터와 화면 분리** — 숫자는 C 파일을 넣는 단위(A07)에서만 바뀌고, 나머지 단위는 표시만 바꾼다.

### 1.2 단위 설계 규칙

| 규칙 | 내용 |
|---|---|
| **R1. 브라우저로 확인 가능** | 단위가 끝나면 로컬 `http.server`에서 눈으로 확인할 수 있다 |
| **R2. B 없이도 확인** | B 연동 단위를 빼면 `?api=off`로 확인 가능 |
| **R3. 숫자는 C 그대로** | 화면 단위는 숫자를 만들지 않는다. 데이터 단위는 `embed_data.py --check`로 확인 |
| **R4. 캐시 갱신** | 화면을 바꾼 단위는 `sw.js` VERSION을 올린다 |
| **R5. 완료 조건은 관찰 가능** | "만들었다"가 아니라 "이 화면에서 이렇게 보인다" |
| **R6. B·C 불가침** | `app/`, `calc_engine/`은 수정하지 않는다. 필요하면 요청·제안으로 남긴다 |

### 1.3 완료 처리 기준

완료 조건을 **실제로 보고** 확인해야 완료다. 하나라도 미확인이면 🔄로 남긴다.

| 브랜치 | `a/<작업명>` (예: `a/dashboard`, `a/pearl-drag`, `a/realestate`) |
