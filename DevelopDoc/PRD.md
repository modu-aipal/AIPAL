| 항목 | 내용 |
|---|---|

## 1. 개요

서울 상권의 매출·점포·시간대·가게 정보를 **3D 지도와 한 화면 리포트**로 보여 주고, 로봇 **펄이**를 통해 자연어 질문을 B에 보내 답을 보여 주는 대시보드.

한 줄 정의: **"숫자를 만들지 않고, C 데이터와 B 답변을 한눈에 보이게 하는 화면."** 매출·점포 숫자는 C 파일 그대로, 질문 답은 B가 계산한 그대로 보여 준다. 대시보드가 하는 계산은 표시용(비중·순위 정렬·검색 필터)뿐이다.

팀 내 위치:

```
사용자 → A(지도·리포트·펄이) ─질문→ B(질문 이해·검증) → C(계산) → B(답변) → A(표시)
              └─ C가 만든 대시보드 데이터(dashboard_data*.json)를 페이지에 내장
A → B 호출은 Vercel 서버 함수(dashboard/api/)를 거친다: 함수가 API 키를 붙여 B로 전달 (PR #17)
```

## 2. 문제 정의

| 문제 | 증상 |
|---|---|
| 상권 데이터가 표·엑셀로만 있다 | 어디가 크고 언제 붐비는지 한눈에 안 들어온다 |
| 숫자만 있고 맥락이 없다 | 시장·도매형 상권(청과상 81% 등)이 일반 상권과 같은 줄에서 비교된다 |
| AI 답변을 믿기 어렵다 | 화면에 출처·계산 방식이 안 보이면 지어낸 숫자인지 알 수 없다 |
| 서버가 꺼지면 아무것도 안 보인다 | 로컬 AI 서버(ngrok)는 언제든 끊길 수 있다 |
| 지도가 장난감처럼 보인다 | 네온 상자만 서 있으면 "여기가 어디지?"가 먼저 든다. 아는 동네를 알아봐야 데이터가 와닿는다 |
| 매출은 있는데 "그 동네에 어떤 가게가 있는지"는 모른다 | 창업 준비자가 경쟁 가게를 직접 찾아야 한다 |

### 우리의 접근

1. **숫자는 C 파일 그대로 내장한다.** `embed_data.py`로 넣고 `--check`로 C 파일과 다른 점이 없는지 확인한다.
2. **AI 답변은 출처를 붙여 보여 준다.** "AI 분석 서버" 배지, 계산 방식, 서버 원문, Mock 배지를 함께 보인다. (C 엔진은 SQL이 아니라 pandas로 계산하므로 B 답은 "SQL 없이(pandas) 계산", 내장 데이터 답은 같은 계산을 SQL로 쓴 설명이다. 실행한 SQL이 아니다)
3. **서버가 없어도 쓸 수 있게 한다.** 내장 데이터로 답할 수 있는 질문은 내장 데이터로 답하고 그렇게 밝힌다.
4. **맥락을 같이 보여 준다.** 시장·도매형 주의 문구, 100곳 중 순위·중간값, 데이터 기준 시점을 함께 표시한다.
5. **실제 서울처럼 보이게 한다.** 위성사진·실제 건물 윤곽·나무로 장소를 알아보게 하고, 데이터 탑만 팀이 만든 건물로 세운다. 보기용 자원은 탑의 높이·색 의미를 바꾸지 않는다.

## 3. 목표 / 비목표

### 3.1 MVP 목표

| # | 목표 | 측정 방법 |
|---|---|---|
| G1 | 숫자 무결성 | `embed_data.py --check` 결과 "바뀐 내용 없음". 펄이 답 숫자가 C 데이터와 일치 |
| G2 | 한눈에 보기 | 지도·순위·리포트·히트맵이 한 화면에 있고 상권을 누르면 모두 같이 바뀜 |

| G4 | 끊겨도 동작 | B 연결 실패 시 오류 화면 없이 안내 + 내장 데이터 답변 |
| G5 | 어디서나 열림 | 데스크톱·폰 브라우저, 앱 설치(PWA), 가로 스크롤 없음 |
| G6 | 비용 | 대시보드 서버·DB 없음 (정적 배포 + Vercel 서버 함수 2개, 무료 범위), 유료 API 없음 |
| G7 | 실제 같은 화면 | 낮에 위성사진·건물·나무로 상권 위치를 알아볼 수 있고, 밤에도 같은 건물 (데스크톱 기준, 폰은 가벼운 버전) |

## 4. 대상 사용자

### 페르소나 A — "상권이 궁금한 소상공인·창업 준비자"
- 지도로 둘러보고 상권을 눌러 본다. "성수에서 카페 차리면 괜찮을까?"를 펄이에게 묻는다
- 니즈: 어디가 크고, 언제 붐비고, 어떤 가게가 이미 있는지
- 이탈 요인: 숫자 덩어리, 로딩만 도는 화면

### 페르소나 B — "숫자를 의심하는 검증자 (심사위원·팀원)"
- 니즈: 이 숫자가 어디서 왔나, AI가 지어낸 건 아닌가
- 보는 곳: 출처·기준 분기 표시, "계산 방식 보기", "서버 원문", 주의 문구

> **설계 원칙:** 보기 좋게 만들되 숫자는 바꾸지 않는다. 모르면 모른다고, 서버 답이 아니면 아니라고 표시한다.

## 6. 기능 요구사항

### 6.1 P0 — MVP 필수

#### F-01. 3D 지도
- 상권 100곳: 리포트 20곳(굵은 탑) + 지도 80곳(가는 탑, 누르면 그 동의 리포트).
- 큰 건물 높이 = 선택한 시간대 매출. 땅 높이는 매출에 더하지 않는다. 작은 건물은 배경 장식.
- 실제 표고(높이 4배 강조)와 한강, 끌어서 돌리기·확대, 시장·도매형 건물 색 구분, 선택 상권 강조.

#### F-02. 순위 · 추이 · 리포트
- 최신 분기(26Q2) 매출 순위 20곳, 분기별 매출 추이(24Q3~26Q2, 표로 보기).
- 리포트: 추정매출·전 분기 대비, 1년 성장, 매출 1위 업종(비중), 피크 시간, 업종별 매출 TOP 8.
- 분기 표시는 데이터의 `quarters`를 따른다. 지도 80곳의 분기가 다르면 그 동은 자기 분기로 표시한다.

#### F-03. 펄이 — 질문과 답
- 말풍선 질문 5개: API 없이 내장 데이터로 즉시 답한다.
- 직접 입력: 질문에 나온 상권이 모두 B 지원 지역(`/health`의 `regions`)이면 `POST /api/dashboard/analyze`로 보낸다. 아니면 내장 데이터로 답하고 그 이유를 밝힌다.
- 답변 표시: "AI 분석 서버" 배지, 줄바꿈 유지, `area` 상권으로 지도 이동, 계산 방식 보기, Mock이면 배지.

#### F-04. 재질문·실패 대응
| 상황 | 화면 |
|---|---|
| 422 `needs_clarification` | 쉬운 안내 + 질문의 지역·업종으로 채운 예시 질문 버튼, B 원문은 "서버 원문"에 접음 |
| 401 / 5xx / 연결 실패 / 150초 초과 | 사유 표시 + 내장 데이터로 답할 수 있으면 "대시보드 데이터로 답했어요" |
| 업종 별칭 (성형외과·피부과 → 일반의원, 카페 → 커피-음료 등) | 데이터의 업종 이름으로 바꿔 예시 질문을 만든다 |

### 6.2 P1 — 확장 (이번 라운드에 구현)

| ID | 기능 | 방식 |
|---|---|---|
| F-05 | 점포 · 객단가 | C 점포 지표 + 100곳 중 순위·중간값, 해석 주의 문구(`cautions`) |
| F-06 | 시간대 히트맵 | 상권별 하루 매출 = 100%, 칸 클릭 → 상권 이동 |
| F-07 | 가게 검색 | 소상공인 상가정보, 상권마다 파일 1개, 상권을 열 때만 불러옴. 대분류 버튼·층 검색·업종 이름 일치 우선 |
| F-08 | 앱 설치 (PWA) | manifest + 서비스 워커, 한 번 연 뒤 오프라인 지도·내장 데이터 |
| F-09 | 펄이 3D | 블렌더 모델(glb), 데스크톱은 3D·표정, 폰·동작 줄이기 설정은 이미지. 끌어서 위치 이동 |
| F-10 | B 호출 프록시 | Vercel 서버 함수가 `B_API_KEY`를 붙여 B로 전달, 페이지는 같은 주소(`self`)로 보냄 (PR #17) |
| F-11 | 카페 점포 답변 | 말풍선 카페 질문에 C `cafe_store`(카페 점포 수·한 곳당 월매출) 문장 (PR #21) |
| F-12 | 도시 비주얼 | 낮: 위성사진 지면·지면 그늘(AO)·OSM 건물 외벽·나무·데이터 탑 Meshy 건물. 밤: 같은 건물 창문 불빛·꼭대기 빛. 폰은 작은 위성사진·나무 1/3·건물 모델은 리포트 20곳만 |
| F-13 | 데이터 탑 건물 5종 | 유진아 Meshy 모델 5세트(아랫부분·몸통·꼭대기)를 탑마다 골고루 섞음. 높이 = 매출은 몸통을 쌓는 개수로 유지 |

### 6.3 향후

- B의 `reason`·`suggested_questions`를 화면 예시 버튼에 쓰기 (Q-02)
- 재질문에 "성형외과는 데이터에서 '일반의원'에 포함돼요" 같은 별칭 설명 한 줄
- 가게 위치를 지도에 점으로 표시
- 데이터 탑 건물 5종 (F-13) — 모델 4세트 제작 후
- 상가 매매 실거래가 (국토교통부 API, 키는 서버 쪽에만)

## 8. 비기능 요구사항

| 구분 | 요구사항 |
|---|---|
| 정확성 | 매출·점포 숫자는 C 파일 그대로. 반올림은 표시용(억 원 소수 1자리)만 |
| 안전 | B 답변은 HTML로 해석하지 않음(글자 그대로 + 줄바꿈). API 키를 페이지에 넣지 않음 |
| 성능 | 서버 없음. 가게 파일은 상권을 열 때만 불러오고 서비스 워커가 저장 |
| 가용성 | B·인터넷이 끊겨도 지도·리포트·말풍선 답은 동작 |
| 접근성 | 동작 줄이기 설정 존중(애니메이션 끔), 폰에서는 3D 펄이 대신 이미지 |
| 반응형 | 데스크톱·태블릿·폰(375px)에서 가로 스크롤 없음 |
| 설정 | B 주소는 `?api=`·`<meta name="aipal-api">`로 변경, 코드 수정 불필요 |
| 언어 | 한국어 단일 |

# AI 분석 서버(B) — 제품 요구사항 문서 (PRD)

| 항목 | 내용 |
|---|---|
| 문서 버전 | v0.1 (main `bbb905a`, PR #31까지 병합 반영) |
| 작성일 | 2026-11-24 |
| 담당 | B (genJ-M) |
| 범위 | 해커톤 MVP — B 역할(AI 분석 서버)만. A(대시보드), C(계산 엔진)는 연동 대상으로만 다룬다 |

---

## 1. 개요

사용자가 자연어로 던진 상권 질문("성수에서 카페 차리면 괜찮을까?")을 **검증된 분석 계획**으로 바꾸고, C의 계산 엔진에서 받은 숫자만으로 **근거가 붙은 답변**을 만들어 A 대시보드에 돌려주는 AI 분석 서버.

한 줄 정의: **"AI는 질문을 해석만 하고, 숫자는 계산 엔진에서만 가져와 검증한 뒤 답하는 서버."** 질문 해석은 로컬 LLM(Ollama)과 규칙 코드가 같이 하되, 계획은 코드가 최종 검증한다. 숫자를 만들지도 고치지도 않는다.

팀 내 위치:

```
사용자 → A(지도·리포트·펄이) ─질문(+직전 질문 history)→ B(질문 이해·계획 검증) → C(계산) → B(검증·답변 구성) → A(표시)
              └─ A → B 호출은 Vercel 서버 함수가 X-API-Key 를 붙여 전달 (PR #17)
```

---

## 2. 문제 정의

| 문제 | 증상 |
|---|---|
| LLM이 숫자를 지어낸다 | 그럴듯하지만 근거 없는 매출·순위가 답으로 나온다 |
| 질문 표현이 사람마다 다르다 | "잘나가는", "뜨는", "한 곳당", "가게별", "전년 같은 분기" 같은 말이 같은 지표를 뜻한다 |
| 모델이 질문을 잘못 해석해도 모른다 | 숫자는 맞는데 질문의 뜻과 다른 답 (예: 전년 대비를 전 분기 대비로 답함) |
| 데이터에 없는 질문에 억지 답을 한다 | 월별 매출, 임대료, 진료과목별 매출을 물어도 숫자를 만들어 낸다 |
| 막히면 사용자가 막막하다 | "답할 수 없어요"만 오면 다음에 뭘 물어야 할지 모른다 |
| 앞 질문을 기억하지 못한다 | "그럼 홍대는?"에 되묻기만 한다 |
| 서버가 공개 주소에 노출된다 | 아무나 호출하면 로컬 PC의 모델과 엔진이 쓰인다 |

### 우리의 접근

1. **계획을 코드가 검증한다.** 모델이 낸 초안(`PlanDraft`)은 참고만 하고, 규칙 코드(`planner.evaluate`)가 질문에서 직접 읽은 값이 모델 값보다 우선한다. 모델이 시간 안에 답하지 못하면 규칙만으로 계획을 만든다 (Ollama가 꺼져 있으면 오류(503)이고, 그때 A 화면은 내장 데이터로 대신 답한다).
2. **숫자는 계산 엔진만.** B는 계산 요청(`CalcRequest`)을 만들고 응답을 검증(`verify_result`)한 뒤 문장으로 옮긴다. 모든 숫자에는 근거(기간·지표·연산)를 붙인다.
3. **모르면 모른다고, 막힐 때는 이유와 제안을 같이 준다.** 서버가 직접 통과 여부를 확인한 질문만 제안한다.
4. **판단 표현도 데이터로 번역한다.** "창업하기 좋은 곳", "수입은 어때"를 임의로 판단하지 않고 점포당 매출·증감 같은 지표와 순위로 바꿔 답하고, 한계 문구를 붙인다.
5. **가정은 숨기지 않는다.** 질문에 없던 기간·지표를 기본값으로 정하면 답변에 "※ 기준:"으로 밝힌다.

## 4. 대상 사용자

### 페르소나 A — "상권이 궁금한 소상공인·창업 준비자"
- 펄이에게 "성수 카페 점포당 매출", "홍대에서 창업하기 좋은 업종은?"처럼 편하게 묻는다
- 니즈: 말투가 달라도 알아듣고, 못 알아들으면 어떻게 물으면 되는지 알려 주는 답
- 이탈 요인: 계속 되묻기만 하는 답, 근거 없는 추천

### 페르소나 B — "숫자를 의심하는 검증자 (심사위원·팀원)"
- 니즈: 이 숫자가 어떤 계산으로 나왔는지, AI가 지어낸 건 아닌지
- 보는 곳: 답변의 근거 줄, 계산 방식 보기("SQL 없이 pandas 계산" 또는 같은 계산을 SQL로 쓴 설명), 한계 문구, Mock 표시

> **설계 원칙:** AI가 말을 잘하는 것보다 틀린 말을 못 하게 하는 것이 먼저다. 애매하면 이어받지 않고, 모르면 안내한다.

## 6. 기능 요구사항

### 6.1 P0 — MVP 필수

#### F-B01. 질문 → 분석 계획
- 지역 20곳·업종 63개·기간(분기)·지표(매출 합계·평균·증감률·점포당·구성비)·정렬·상위 N을 읽는다.
- 모델 초안은 30초·400토큰 안에서만 쓰고, 실패·시간 초과면 규칙만으로 진행한다.
- 코드가 읽은 값이 모델 값보다 우선한다.

#### F-B02. 계산 요청·검증
- 계획을 계산 규격(1.0, 점포당·비율은 1.1)으로 바꿔 C에 보낸다 (`CALC_MODE=http`).
- 응답을 검증(`verify_result`)해 어긋나면 답하지 않고 오류로 돌린다.
- 증감의 기준 기간은 요청에 명시해 보낸다.

#### F-B03. 답변 구성 (`{area, sql, text}`)
- 결론 → 목록 → 해석 → 근거·가정(※) 순서의 줄바꿈 구조.
- 순위 질문의 하한: 증감·점포당 순위는 매출 1억 원 이상 그룹만, 폐업률·개업률 순위는 점포 평균 30개 이상 그룹만.
- Mock이면 표시한다.

#### F-B04. 막힘 응답
| 상황 | 응답 |
|---|---|
| 필수 조건이 빠짐·애매함 | HTTP 422 `needs_clarification` + 이유 + 서버가 통과를 확인한 제안 질문 |
| 데이터 정의 질문 | HTTP 200 `status=info` (고정 설명) |
| 범위 밖 기간(2021Q1~최신 분기 밖) | 되묻기 (`bad_period`) |
| 계산 실패 | 5xx 사유 (숫자를 내지 않음) |

#### F-B05. 접근 제한
- `X-API-Key` 헤더 검증(`secrets.compare_digest`), `/health`만 인증 없이 허용, CORS는 환경변수로 제어.
