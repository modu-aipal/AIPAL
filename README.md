# AIPAL — 서울 상권 AI 분석

서울 상권 100곳의 매출을 실제 서울처럼 보이는 3D 지도 위 건물 높이로 보여 주고, 화면 속 로봇 **펄이**에게 자연어로 물으면 계산 엔진의 숫자로 답해 주는 서비스입니다.

> 설계 원칙: **AI는 질문을 해석만 하고, 숫자는 계산 엔진에서만 나옵니다.** 화면은 숫자를 만들지 않고 그대로 보여 주며, 답변은 근거와 한계를 함께 밝힙니다.

- 공개 화면: https://aipal-sangkwon-pulse.vercel.app
- 데이터: 서울 열린데이터광장 추정매출·점포(행정동), 공공데이터포털 소상공인 상가정보
- 문서: [`DevelopDoc/`](./DevelopDoc) (PRD · TECH_SPEC · WORK_UNITS · FINAL_CHECKLIST)

## 전체 구조

```
사용자 → A 대시보드(지도·리포트·펄이) ─질문(+직전 질문)→ B AI 분석 서버 → C 계산 엔진
                                                         └← 검증된 숫자 + 근거 ← 계산 결과
A → B 호출은 Vercel 서버 함수가 API 키를 붙여 전달 (키가 브라우저에 노출되지 않음)
```

| 역할 | 담당 | 한 일 | 위치 |
|---|---|---|---|
| **A** 대시보드 | maidysound-netizen | 3D 지도·리포트·가게 검색·펄이 화면, Vercel 배포, B 호출 프록시 | [`dashboard/`](./dashboard) |
| **B** AI 분석 | genJ-M | 질문 해석·분석 계획 검증·계산 요청·답변 구성, API 키 보호 | [`app/`](./app) |
| **C** 데이터·계산 | castlegyun | 공공데이터 정의 확정, 계산 엔진, 정답표·검증 | [`calc_engine/`](./calc_engine) |

## 화면에서 할 수 있는 것 (A)

- **3D 지도**: 상권 100곳을 건물 높이(고른 시간대의 매출)로 보고, 끌어서 돌리고 확대합니다. 굵은 탑 20곳은 리포트, 가는 탑 80곳은 누르면 그 동의 리포트가 열립니다.
- **상권 리포트**: 추정매출·전 분기 대비·1년 성장·매출 1위 업종·피크 시간, 점포·객단가·개업률·폐업률, 업종별 TOP 8, 주의 문구, 시간대 히트맵, 가게 검색(99,735곳).
- **펄이**: 말풍선 질문은 내장 데이터로 즉시 답하고, 직접 입력한 질문은 B 서버가 계산한 답을 보여 줍니다. B가 되물으면 이유와 눌러서 다시 물을 예시를 줍니다.
- **끊겨도 동작**: B가 꺼져도 지도·리포트·말풍선 답은 그대로 동작하고, 내장 데이터로 답했음을 밝힙니다.
- **앱처럼 설치**(PWA), 폰 화면 지원.

## AI가 답하는 방식 (B)

1. **질문 해석**: 지역 20곳·업종 63개·기간·지표를 읽습니다. 로컬 LLM(Ollama `llama3.1:8b`)이 계획 초안을 만들고, 규칙 코드가 읽은 값이 모델 값보다 우선합니다. 모델이 없어도 규칙만으로 동작합니다.
2. **계산 요청·검증**: 계획을 계산 규격으로 바꿔 C에 보내고, 돌아온 결과를 검증한 뒤에만 문장으로 만듭니다.
3. **답변**: 결론 → 목록 → 해석 → 근거·가정(※) 순서입니다. 질문에 없던 기간·지표를 기본값으로 정하면 "※ 기준:"으로 밝히고, 증감은 전 분기 / 전년 같은 분기 중 무엇과 비교했는지 적습니다.
4. **막힐 때**: 지어내지 않고, 이유와 서버가 직접 통과를 확인한 질문 예시를 함께 안내합니다.
5. **판단 표현**: "창업하기 좋은 곳", "수입은?" 같은 말은 점포당 매출·증감 지표와 같은 조건의 순위로 번역하고 "매출만으로 판단할 수 없다"는 한계를 붙입니다.
6. **이어 묻기**: "그럼 홍대는?"처럼 앞 질문을 가리키면 직전 질문 3개에서 빠진 조건만 이어받습니다 (서버는 대화를 저장하지 않습니다).

자세한 규격: [`docs/DASHBOARD_API.md`](./docs/DASHBOARD_API.md)

## 데이터와 계산 (C)

- 허용된 계산 연산(합계·평균·증감률·비율·비중·점포당)만 실행하고, 계산식·출처·안내를 응답에 함께 담습니다.
- 정의가 애매한 컬럼('당월 매출' = 분기 3개월 합계 등)은 제공 기관에 문의해 확정했습니다.
- 정답표를 두 방법(pandas / 파이썬 기본 csv)으로 계산해 같을 때만 기록하고, 일부는 상권분석서비스 사이트 값과 대조했습니다.
- 출처·정의·한계: [`docs/DATA.md`](./docs/DATA.md)

## 빠른 시작

B 서버, C 엔진, 테스트는 저장소 최상단에서 실행합니다.

```powershell
python -m venv .venv
.\.venv\Scripts\pip install -r requirements.txt
.\.venv\Scripts\pip install -r calc_engine\requirements.txt
Copy-Item .env.example .env
```

```powershell
.\.venv\Scripts\python -m uvicorn calc_engine.main:app --port 8100   # C 계산 엔진
.\.venv\Scripts\python -m uvicorn app.main:app --port 8000           # B AI 분석 서버 (Docs: http://127.0.0.1:8000/docs)
.\.venv\Scripts\python -m pytest                                      # 전체 테스트
```

- B는 로컬 Ollama(`OLLAMA_MODEL`)와 C 엔진(`CALC_ENGINE_URL`)을 사용합니다. 설정은 [`.env.example`](./.env.example)을 참고하세요.
- 대시보드만 보려면 `python -m http.server 8765 --directory dashboard` 후 http://localhost:8765 (B 없이도 지도·리포트·말풍선 질문 동작).
- 공개 주소로 열려면 `start.ps1`이 B 서버와 ngrok을 함께 켭니다.

## 보안

- B는 `X-API-Key` 헤더가 없으면 401입니다 (`/health`만 열려 있음). 키는 `.env`에만 두고 저장소에 올리지 않습니다.
- A 화면에는 키가 없습니다. 키는 Vercel 환경변수(`B_API_KEY`)에만 있고 서버 함수([`dashboard/api/`](./dashboard/api))가 붙여 B로 전달합니다. 프록시 예시: [`docs/b-role/a-proxy/`](./docs/b-role/a-proxy)
- B의 답변은 화면에서 HTML이 아닌 글자로만 표시합니다. 계정·개인정보·분석 도구는 없습니다.

## 팀 기여

### A — 화면 · 배포
- **3D 상권 지도**: 지형·한강·상권 100곳, 건물 높이 = 시간대 매출, 낮·밤 도시 비주얼
- **리포트·히트맵·가게 검색**: C 데이터를 그대로 보여 주고, 시장·도매형 상권 주의 문구와 100곳 중 순위를 함께 표시
- **펄이**: 말풍선 질문·직접 질문 라우팅·되묻기 예시 버튼, B가 끊겨도 내장 데이터로 답하는 흐름
- **배포와 보안**: Vercel 배포, API 키를 서버 함수로 붙이는 프록시, `sw.js` 버전 관리로 최신 화면 보장
- 자세한 내용: [`dashboard/README.md`](./dashboard/README.md)

### B — AI 분석
- **분석 서버**: FastAPI + 로컬 Ollama. 질문 → 계획 → 계산 → 검증 → 답변 (`POST /api/dashboard/analyze`)
- **계획 검증**: 모델 초안은 참고만 하고 규칙 코드가 읽은 값이 우선. 모델이 없어도 동작
- **질문 이해**: 지역 20곳·업종 63개·기간, 점포당·구성비·증감(전 분기/전년)·합계, 판단 표현 8종을 지표로 번역
- **막힘 대응**: 이유와 서버가 통과를 확인한 제안 질문을 함께 안내, 데이터에 없는 질문은 지어내지 않음
- **이어 묻기·창업 답변**: 직전 질문 3개로 조건 이어받기, 결론 문장 + 같은 조건 20곳 중 순위 + 이어 물어보기
- **보안**: `X-API-Key`로 공개 서버를 보호하고, 키가 브라우저에 들어가지 않도록 프록시 예시 제공
- **검증·운영**: 테스트 자동화(저장소 전체 434개 통과), 질문 평가셋(기본 116 + 처음 본 표현 21), 서버·ngrok 운영과 병합 후 재시작
- 자세한 내용: [`docs/b-role/`](./docs/b-role)

### C — 데이터 · 계산 · 검증
- 공공데이터 준비와 **정의 확정**: '당월 매출'이 분기 3개월 합계인지 등 애매한 부분을 제공 기관에 문의해 공식 답변으로 확정
- **계산 엔진** (`calc_engine/`, `POST /calculate`): 허용 연산 6개, 오류 규칙, 계산식·출처를 응답에 함께 담기
- **정답표와 테스트**: 정답을 두 방법(pandas / 파이썬 기본 csv)으로 계산해 같을 때만 기록, 일부는 상권분석서비스 사이트 표시값과 대조
- **대시보드용 데이터**: 점포 데이터 연결, 20곳·지도 80곳 데이터 파일, 업종별 점포 수·점포당 월매출
- **검증**: 펄이 답변 19개 정답 대조, 펄이 데이터 설명 문구 검수(B12), 배포 화면 사용자 흐름 점검
- 자세한 내용: [`docs/c-role/`](./docs/c-role)

## 회고

### B
- **가장 크게 배운 것**: 로컬에서 AI를 API로 연결해 보는 것이 처음이었다. 연결이 되는 것을 직접 확인하면서 작동 원리를 대략 이해하게 되었고, 이것이 나만의 AI를 만들기 위한 첫 단계라고 느꼈다.
- **어려웠던 점**: AI가 질문을 해석하고 데이터를 쓰는 과정에서 이해하지 못하는 부분이 있었다. 이를 잡으려면 예시 질문으로 검사하고 답변을 준비해야 했고, 이 과정에 가장 시간이 걸렸다.
- **다음에 해 볼 것**: AI를 더 적극적으로 활용하겠다. 예를 들어 분석 결과로 실제 보고서를 작성해 다운로드할 수 있게 하는 식으로 확장하고 싶다.

### C
- **가장 크게 배운 것**: "숫자는 계산 엔진이 낸다"만으로는 부족했다. 펄이는 숫자를 하나도 지어내지 않았지만, 전년 대비를 물었을 때 전 분기 대비로 답했다. 검증은 **숫자와 질문의 뜻 둘 다** 봐야 한다.
- **다음에 다르게 할 한 가지**: 계산 규격을 **실제 데이터를 본 뒤에** 합의하겠다. 이번에는 데이터를 받기 전에 만든 규격(v1.0)이 실제 데이터와 달라서(월 단위를 가정했지만 실제는 분기 단위, 업종 이름도 다름) v1.1 제안이 따로 필요했다. 배운 것과 같은 교훈이다. 실제 데이터와 실제 뜻을 먼저 봐야 한다.

### A
- **가장 크게 배운 것**: 화면은 숫자를 만들지 않고 받은 숫자를 정확히 보여 주는 역할이라는 것. 3D 지도를 아무리 화려하게 꾸며도 건물 높이(매출)와 색(1위 업종)의 뜻은 바뀌면 안 된다. 보기 좋은 것과 정확한 것을 함께 지키는 것이 대시보드의 일이었다.
- **어려웠던 점**: 내 컴퓨터에서 잘 되는 것과 실제 사용자 화면에서 잘 되는 것은 달랐다. 고쳤는데도 예전 화면이 남거나(서비스 워커 캐시), API 키를 화면에 넣을 수 없어서 서버 함수로 다시 연결하거나, 팀이 만든 3D 건물 모델이 너무 무거워 줄여야 했다. 배포된 주소에서 직접 확인하기 전까지는 끝난 게 아니었다.
- **다음에 다르게 할 한 가지**: 화면을 꾸미기 전에 B·C와 "무엇을 어떤 형식으로 주고받을지"를 먼저 정하겠다. 이번에는 응답 형식이 바뀔 때마다 화면을 다시 맞춰야 했다. 규격을 먼저 맞추면 디자인에 더 많은 시간을 쓸 수 있다.
